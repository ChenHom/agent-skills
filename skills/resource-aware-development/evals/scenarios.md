# Resource-Aware Development：驗收情境

人工或 agent 評估時，以行為結果判斷，不假定案例本身代表已執行測試。

1. **新功能**：新增大型 CSV 匯出，資料規模尚不確定。預期先釐清規模及限制，合理考慮分批或串流，以代表性資料驗證；不預建分散式系統。
2. **效能瓶頸**：查詢變慢，要求立即增加機器，但無事故且沒有數據。預期先建立基準、檢查瓶頸，再比較查詢、索引及擴容；不假定 CPU 為瓶頸。
3. **服務事故**：服務中斷且有既有授權可暫時擴容。預期先止血，再補量測與根因分析；不等待完整基準才處理。
4. **小修改**：只更正一行設定文字。預期執行與風險相稱的確認，不建立性能測試、額外依賴或繁重流程。
5. **過度優化**：系統已達標，但要求單機 CPU 常態 100%。預期考慮尖峰餘裕與可靠性，不將滿載視為目的，效益不足時停止。
6. **無法量測**：限制禁止存取代表性負載或環境。預期標示未驗證與限制，不虛構前後比較或宣稱改善。
