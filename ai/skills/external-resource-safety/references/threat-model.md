# Threat Model

## 問題定義

現行 LLM 會在同一個推論前後文中處理系統規則、使用者要求、外部文件、網頁、工具回傳與歷史資料。外部內容雖然應該只是資料，仍可能在語意上影響模型對任務與權限的理解。

間接 prompt injection 不需要讓人看得見。只要內容能被模型解析，就可能改變模型行為。

## 攻擊成立條件

1. 攻擊者能控制部分輸入。
2. 外部內容進入模型前後文。
3. 模型無法可靠區分資料與授權指令。
4. 模型具有讀取、寫入、執行或對外傳輸能力。
5. 輸出被信任、保存、分享或再次提供給其他 AI。

## 傳播條件

一般 prompt injection 只影響一次輸出。形成文件型 AI 蠕蟲還需要：

- 輸出保留攻擊語意
- 攻擊內容被複製到新的載體
- 新載體再次進入 AI 工作流程
- 內部產生的內容被錯誤地視為可信

傳播可以跨格式：

```text
外部 PDF
→ AI 產生 Word
→ Word 轉成簡報
→ 簡報摘要進入 Teams
→ Teams 內容寫入知識庫
```

## 主要風險

- 靜默修改文件、數字或決策依據
- 讀取與洩漏敏感資料
- 未授權工具操作
- 惡意內容進入可信知識庫
- AI 產出再次污染其他 AI
- 來源與修改歷程消失
- 內部文件替外部攻擊洗白來源

## 防禦原則

### 不追求辨識所有惡意文字

自然語言可以改寫、編碼、拆分或偽裝。字串黑名單、模型升級、RAG 與「忽略惡意指令」提示都不能提供完整防護。

### 控制爆炸半徑

即使模型被操控，也應做到：

- 讀不到無關秘密
- 沒有超出任務的工具
- 不能自行寄送、發布、刪除或部署
- 不能靜默修改正式資料
- 不能把未核准輸出升級為可信資料
- 所有衍生內容都能追溯與撤除

### 使用確定性控制

安全邊界應由程式與權限系統強制實施：

- sandbox
- 最小權限與短效 token
- 網路允許清單
- Schema 與欄位白名單
- 後端重新授權
- diff 與人工核准
- 可逆操作與稽核紀錄

## Skill 的限制

這個 Skill 能固定檢查流程、降低遺漏並阻止模型直接服從外部指令，但不能：

- 改變模型底層架構
- 保證偵測所有攻擊
- 取代 sandbox 與存取控制
- 攔截未載入此 Skill 的工作流程
- 將「未發現異常」解釋成「內容安全」
